Overview

  • Problem 1: You get recorded episodes from a fixed policy. Estimate the value of each state.
  • Problem 2: The agent chooses its own actions. Learn the value of each (state, action) pair, then return the best action for each state.
  • Problem 3: You don't write a new agent. You design an MDP where an exploration bonus beats ε-greedy.

Notation

SymbolNameMeaning
V(s)State valueExpected total discounted reward starting from state s and following the policy. Problem 1 computes this.
Q(s, a)Action valueExpected total discounted reward if you take action a in state s, then act optimally. Problem 2 computes this.
π(s)PolicyThe action to take in state s. After learning, it's the action with the highest Q(s, a).
γ (gamma)Discount factorMultiplier applied to each future reward per step. With γ = 0.8, a reward one step away is worth 80% of the same reward now.
α (alpha)Learning rateHow much each new sample moves the estimate. α = 0 ignores the sample; α = 1 replaces the estimate with the sample.
ε (epsilon)Exploration rateProbability of taking a random action instead of the best one.

The gridworld

States are (x, y), with x increasing to the right and y increasing upward. Actions are up, down, right, left, in that order.

  • The intended move succeeds with probability 0.8. Otherwise you move in one of the two perpendicular directions (0.1 each).
  • Moving into a wall leaves you where you are.
  • The goal and the obstacle are absorbing: once there, every action keeps you there with reward 0.
  • The +100 or −1000 is paid on the step that enters the goal or obstacle.

Rewards: +100 for entering the goal, −1000 for entering the obstacle, 0 otherwise. In 2C the obstacle penalty is −500. γ = 0.8 on the grid and 0.95 in Problem 3.

Episode format

An episode is a list of tuples (state, action, next_state, reward). The reward belongs to that transition. generate_episodes stops when next_state is the goal or obstacle, so the last tuple is the one carrying the +100 or −1000.

Don't read mdp.T or mdp.R in your learners. In Problem 2, get next states and rewards only from sample_environment. The fixed policy in Problem 1 is "always move right."

1A · Direct evaluation

First-visit Monte Carlo · 15 points · Lecture 13

direct_evaluation(episodes, gamma) → dict[state, value]

For each state, look at what happened after it in each episode, add up the discounted rewards, and average across episodes. You don't need the transition or reward model.

Step 1: the return from a visit

Start at the tuple where the state appears. Take that tuple's reward at full value. Multiply the next tuple's reward by γ, the one after by γ², and so on to the end of the episode. Add them up.

G = ri + γ·ri+1 + γ²·ri+2 + … + (last reward in the episode)

Step 2: average over episodes

V(s) = average of G over every episode where s appears, using only its first appearance

First visit: if a state appears more than once in the same episode, only compute G from its first appearance and ignore the rest. Reset this tracking at the start of each new episode. (Counting every appearance is "every-visit" Monte Carlo. Don't do that here.)

Try it: compute a return

An always-right episode. Drag the slider to change γ.

Hint 1: bookkeeping. Keep a running sum and a count for each state instead of storing every return. Use a seen set that you reset at the start of each episode. States are tuples, so you can use them directly as dictionary keys.
Hint 2: start discounting at the visit, not at the start of the episode. If the state first appears at index i, sum rewards from episode[i] onward. episode[i]'s reward gets multiplied by 1, not by γi. Discounting from the start of the episode makes states visited later look too small.
Hint 3: loop structure. 
sums, counts = {}, {}
for episode in episodes:
    seen = set()
    for i, (s, a, s2, r) in enumerate(episode):
        if s in seen:
            continue
        seen.add(s)
        G = 0
        discount = 1
        for (_, _, _, rk) in episode[i:]:
            G += discount * rk
            discount *= gamma
        sums[s] = sums.get(s, 0) + G
        counts[s] = counts.get(s, 0) + 1

V = {s: sums[s] / counts[s] for s in sums}
States that only ever appear as next_state (like the goal and obstacle) get no samples. Add them to V with value 0. If an episode starts on a sink, it has one tuple with reward 0, which correctly gives that state a value of 0.

1B · Sample sensitivity

Written · 10 points · Lecture 13's critique of direct evaluation

Rerun 1A with num_episodes = 100, 1,000, 10,000, and 100,000, a few times each. Note which states' values stabilize and which keep changing between runs.

error in V(s) ≈ (spread of a single return) / √(number of returns collected for s)

"Number of returns" means first visits to that state, not total episodes. The spread is large because a single return can be −1000 (slipped into the obstacle) or +100 (reached the goal).

Hint 1: what to look for. States on the always-right path, especially the right column, get visited a lot and stabilize first. States that are rarely visited stay noisy much longer. The key observation: at 100 episodes, runs disagree; at 100,000, they agree.
Hint 2: why it needs so many samples. Direct evaluation doesn't use the structure of the MDP. Learning that (2,1) usually leads to +100 doesn't help the estimate for (1,1) at all; (1,1) only improves from its own episodes. So two states that lead to the same next state can have very different estimates for a long time. This is the lecture slide asking how B and E can have different values when both go to C.
Hint 3: an outline for your answer.
  1. Name a state that was still changing at 1,000 episodes and say roughly when it stabilized.
  2. Explain the square root: 4× the visits only halves the error.
  3. Give the structural reason: each state learns only from its own returns, and those returns mix +100 and −1000.

1C · Temporal difference (TD) learning

15 points · Lecture 13

td_learning(episodes, gamma, alpha) → dict[state, value]

Still a fixed policy. The difference from 1A: instead of summing all the future rewards, you use your current estimate of the next state's value as a stand-in for them. That lets you update after every single transition.

target = r + γ·V(s')

V(s) ← (1 − α)·V(s) + α·target

Equivalently: V(s) ← V(s) + α·(target − V(s)). Any state you haven't seen yet has value 0.

Update on every tuple, including repeated states. Don't reset V between episodes. Don't add up future rewards yourself: V(s') already stands in for them, so doing both double-counts.

Try it: one pass by hand

The same short episode as 1A: (1,1) → (2,1) with reward 0, then (2,1) → goal with reward 100. All values start at 0. Notice that when (1,1) is updated, V(2,1) is still 0, so (1,1) learns nothing from the +100 on this pass. It only picks that up on a later episode.

Hint 1: order. Process each episode from first tuple to last. Use V(s') as it is at that moment, which is usually what earlier episodes taught it.
Hint 2: entering the goal or obstacle. This is a normal update for the state you left, with reward +100 or −1000. The sink's own value is 0, so the target is just the reward. No extra update is needed after the episode ends.
Hint 3: loop structure. 
V = {}
for episode in episodes:
    for (s, a, s2, r) in episode:
        target = r + gamma * V.get(s2, 0.0)
        old = V.get(s, 0.0)
        V[s] = (1 - alpha) * old + alpha * target
Afterward, make sure every state that only appeared as s2 is in V with value 0. The action is unused: the policy is fixed, so it's already reflected in the transitions you were given.

1D · Learning rate

Written · 10 points · the exponential moving average slide

Rerun 1C with α = 0.00001, 0.0001, 0.001, 0.01, 0.1, and 0.5. The TD update is an exponential moving average: older samples get exponentially less weight.

weight on the sample from k updates ago = α·(1 − α)k

Rule of thumb: the estimate effectively averages the last 1/α updates of that state. Half the weight is on the last 0.7/α updates.

αEffective windowWhat you should see (100,000 episodes)
0.00001~100,000 updatesMost states aren't updated nearly that often, so values stay close to 0. Too slow.
0.01~100 updatesAverages out the slip noise on this small grid without ignoring most of the data. This is the notebook's default.
0.5~2 updatesThe last sample dominates. One slip into the obstacle (−1000) swings a neighbor's value hugely negative, and the next normal step swings it back. Too noisy.
Hint 1: be specific. For each regime, cite a state you actually looked at and what its value did. "Too small underfits, too big overfits" isn't enough; use the 1/α window to explain why.
Hint 2: larger MDPs. In a bigger MDP, each state gets updated less often, so the "too slow" problem shows up even at moderate α. Lecture 13's advice is to decrease α over time, but not so fast that later samples stop mattering. Rarely visited states, and the fact that early estimates of V(s') are wrong, are why no single α works everywhere.

2A · Q-learning

Random actions · 15 points · Lecture 14

q_learning(num_episodes, mdp, gamma, alpha, max_steps=100) → Q, policy

Why Q instead of V? With only V(s), you can't pick an action without knowing the transition model. With Q(s, a), you just pick the action with the highest value.

Q-learning uses the same update as TD, but on (state, action) pairs. It is off-policy: the target assumes you'll act optimally from the next state, even if you're currently acting randomly.

target = r + γ·maxa' Q(s', a')

Q(s, a) ← (1 − α)·Q(s, a) + α·target
π(s) = argmaxa Q(s, a)

The starter code already initializes Q to zeros, loops over episodes, picks a random start state with random.choice(list(mdp.S)), stops at a sink or after max_steps, and chooses actions with random.choice(mdp.A). You need to: sample the environment, apply the update, move to the next state, and build the policy after all episodes.

Try it: one Q update

Hint 1: which action goes in the target. Use the max over all actions in the next state. Not the action you'll actually sample next, and not the action you just took. Using the next sampled action would be SARSA (on-policy). Q-learning uses the max, which is why it can learn the optimal policy even while acting randomly.
Hint 2: entering a sink. Call sample_environment, update Q[state][action], then set state = next_state. If the next state is the goal, its Q values are all 0 (never updated, since you never act from a sink), so the target is just the +100. The while loop condition ends the episode. Don't add any extra random calls.
Hint 3: the policy, and why random calls matter. Build the policy once, after all episodes: 
policy = {
    s: max(mdp.A, key=lambda a: Q[s][a])
    for s in Q
}
On ties, max returns the first action, so an all-zero row (like a sink) gives up. Keep the starter's random.choice calls exactly where they are. An extra random call or a random.seed inside your function changes the random sequence, and the numerical test will fail even if your update is correct.

2B · ε-greedy Q-learning

10 points · Lecture 14

q_learning_epsilon_greedy(..., epsilon, max_steps=100) → Q, policy

Copy 2A. The update stays the same. Only action selection changes:

With probability ε: pick a uniformly random action from all actions.
Otherwise: pick argmaxa Q(s, a).

The random choice includes the current best action. Don't exclude it. With ε = 0.5 you follow the best action about half the time, so you learn a sharper Q table than 2A in the same number of episodes.

Hint 1: the exact code the test expects. Flip the coin first, then pick: 
if random.uniform(0, 1) < epsilon:
    action = random.choice(mdp.A)
else:
    action = max(mdp.A, key=lambda a: Q[state][a])
The greedy branch must not call random. Everything else (episode start, Q update) is the same as 2A.
Hint 2: greedy action vs. returned policy. The else branch uses the current Q, which changes as you learn. The policy you return is built once from the final Q, after the loop. Both should break ties the same way (first action in mdp.A).

3A · Design an MDP where the exploration bonus wins

5 points · Lecture 14, exploration functions · the notebook allows LLM help here

build_exploration_mdp() → (mdp, start)

You don't implement either agent. The grader trains both on your MDP with these settings:

  • 500 episodes, max 50 steps each, every episode starting at start
  • α = 0.1, ε = 0.1, bonus size k = 1, success probability 0.8, γ = 0.95

A policy counts as near-optimal if its true value at start is at least 90% of the optimal value. To pass, the exploration agent must be near-optimal on at least 8 of 10 seeds, and ε-greedy on at most 2 of 10.

The exploration agent

f(s, a) = Q(s, a) + k / (N(s, a) + 1)
Q(s, a) ← (1 − α)·Q(s, a) + α·[r + γ·maxa' f(s', a')]

N(s, a) is how many times action a has been taken in state s. The agent always picks the action with the highest f, not the highest Q. An untried action gets a bonus of k = 1.

How build_graph_mdp works

  • Every edge in the graph is an action, available in every state.
  • If the edge doesn't touch your current node, nothing happens (you stay put, reward 0).
  • If it does, you move to the other end with probability 0.8, or stay put with probability 0.2.
  • The only reward is +100 for arriving at the goal. The goal is absorbing.
  • The graph must be a tree with at most 16 nodes. Check with networkx.is_tree.

Why the bonus helps

Until the goal is reached, every reward is 0, so ε-greedy's Q values are all 0. Its "best" action is a random tie. Since most edges don't touch the current node, most actions do nothing, and the agent mostly stays in place.

The exploration agent's target uses max f(s', ·). A next state with untried actions has f = 1; a state where everything has been tried has smaller f. So moving to a new node scores higher than staying put, even before any reward is found. This pulls the agent toward unexplored nodes. Once it finds the +100, that dwarfs the bonus of 1, and the agent just heads to the goal.

Hint 1: path length is the main knob. Side branches help less than you'd think; a random walker can still stumble onto a short path. What defeats ε-greedy is a long chain of required edges: picking the right edge out of all edges, many times in a row, within 50 steps, is very unlikely. Note that position resets to start every episode, but Q and N persist, so the exploration agent keeps making progress across episodes.
Hint 2: tuning. The test prints how many seeds were near-optimal for each agent.

  • If the exploration agent fails too often, the path is too long to finish in 50 steps: make it shorter.
Each correct move succeeds only 80% of the time, so a path of length L takes about L / 0.8 steps, which must fit in 50. Don't put the start on the goal.
